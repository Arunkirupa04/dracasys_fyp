## 1. History check — has this formula ever changed?

Before writing a fix, I traced `compute_adaptive_threshold()` /
`AdaptiveThresholdSimulator` across every generation of the drift-aware
notebook that exists in this repo:

| Generation | File | `ADAPTIVE_ALPHA` | `BENIGN_BUFFER_SIZE` | Estimator formula |
|---|---|---:|---:|---|
| Legacy v1 | `output-legacy-experiments/mdc_drift_aware_output.ipynb` | 2.5 | 100 | `median(buf) + alpha * std(buf)` |
| Jul-24 integrity archive | `output-legacy-2026-07-24/mdc_drift_aware_output.ipynb` | 2.5 | 100 | `median(buf) + alpha * std(buf)` |
| 25-07 remediation | `output-legacy-kaggle-2026-07-25/mdc_drift_aware_output.ipynb` | 2.5 | **500** (r1 changelog: "aligned to proposal's 500–1000") | `median(buf) + alpha * std(buf)` |
| **Final (current)** | `final/kaggle-source/mdc_drift_aware_kaggle.ipynb` | 2.5 | 500 | `median(buf) + alpha * std(buf)` |

**Finding: across four remediation cycles spanning the entire project
history, every fix touched something else — the score-invert convention, the
threshold provenance/integrity gates, the buffer size, timestamp ordering —
but the core estimator formula itself, `median + α·std`, has never been
changed or root-caused.** The 25-07 revision-2 status banner documents fixing
a *crash* in the fine-tune cell (empty benign slice) in the same notebook, but
says nothing about the adaptive threshold silently producing zero alerts —
because the notebook's own reporting cells (`adaptive_report.json`,
`matched_policy_comparison.json`) only ever surface *last-half* metrics, so a
mechanism that fails from step ~159 onward (3% into the stream) looks, from
the last-half summary alone, like "adaptive collapses under drift" rather
than "adaptive was already broken before the drift period began." That framing
gap is why this has persisted through every prior cycle.

One more relevant clue already in the code: the docstring on
`compute_adaptive_threshold()` says:

> "Using alert space ensures the rule is invariant to `SCORE_INVERT` and
> prevents the artifact where median+std on negative inverted scores exceeds
> all benign values (spurious 0% FPR)."

This shows the original author **was** aware of a threshold-escaping-the-score-range
failure mode, and the alert-space unification (fixed in the Jul-24 cycle) does
correctly prevent one specific version of it (sign-convention/double-invert
driven). But it does not prevent the version actually occurring here, which is
driven by the **heavy-tailed variance of the benign score distribution itself**,
not by a sign/invert bug — a different mechanism than the one the comment
guards against. This is a subtle but important distinction for the thesis
Discussion: two separate threshold-escapes-range bugs exist in this project's
history, one fixed (invert-driven), one not yet fixed (variance-driven).

## 2. Exact current code (what's being replaced)

All of the following live in **cell 10** of `mdc_drift_aware_kaggle.ipynb`
(the "§3b Evaluation helpers" cell — the readable, self-contained utilities
cell; there is no separate `mdc_eval_utils.py` file in this repo, so cell 10
*is* the source of truth):

```python
def compute_adaptive_threshold(
    benign_alert_scores: Sequence[float],
    alpha: float = 2.5,
    min_samples: int = 5,
) -> float:
    """
    Benign-calibrated adaptive threshold in alert space.
    threshold = median(benign) + alpha * std(benign)
    """
    buf = np.asarray(benign_alert_scores, dtype=np.float64)
    if len(buf) < min_samples:
        return float(np.median(buf)) if len(buf) else 0.0
    return float(np.median(buf) + alpha * np.std(buf))
```

### 3.2 Cell 10 — replace `compute_adaptive_threshold`, add a governor, thread it through the simulator

```python
def compute_adaptive_threshold(
    benign_alert_scores: Sequence[float],
    alpha: float = 2.5,
    min_samples: int = 5,
    estimator: str = "quantile",
    target_percentile: float = 72.0,
    max_seen: Optional[float] = None,
) -> float:
    """
    Benign-calibrated adaptive threshold in alert space.

    estimator="median_std" (legacy): threshold = median(benign) + alpha*std(benign).
    Kept only for ablation — on this dataset the benign score distribution is
    heavy-tailed (std comparable in magnitude to the median itself), so
    median+alpha*std reliably overshoots the achievable score range within the
    first few hundred calibration samples, producing zero alerts for the rest
    of the stream regardless of alpha (verified for alpha in [1.5, 3.0]).

    estimator="quantile" (default): threshold = quantile(benign, target_percentile).
    A sample quantile is always within the sample's own observed range, so it
    cannot overshoot a hard score ceiling the way a parametric mean/median +
    k*sigma rule can under heavy-tailed data.
    """
    buf = np.asarray(benign_alert_scores, dtype=np.float64)
    if len(buf) < min_samples:
        thr = float(np.median(buf)) if len(buf) else 0.0
    elif estimator == "median_std":
        thr = float(np.median(buf) + alpha * np.std(buf))
    elif estimator == "quantile":
        thr = float(np.quantile(buf, target_percentile / 100.0))
    else:
        raise ValueError(f"Unknown estimator: {estimator!r}")
    # Governor: a threshold above every score observed anywhere so far can
    # never be crossed again -- refuse it and fall back to the running max.
    if max_seen is not None and thr > max_seen:
        thr = max_seen
    return thr
```

```python
            self.current_threshold_alert, self.invert)

        alert_s = float(to_alert_score(np.array([score_raw]), self.invert)[0])
        self._max_alert_seen = max(self._max_alert_seen, alert_s)   # NEW: track ceiling every step
        if label == 0:
            self.benign_alert_buf.append(alert_s)
            if len(self.benign_alert_buf) > self.buffer_size:
                self.benign_alert_buf.pop(0)
        self._maybe_update(step)
        self.threshold_trace_alert.append(self.current_threshold_alert)
        self.threshold_trace_raw.append(self.current_threshold_raw)
        return self.current_threshold_raw

            to_alert_score(np.array([score_raw]), self.invert)[0]
            >= self.current_threshold_alert)
```

Notes on this diff:
- `_max_alert_seen` is updated from **every** observed score (benign and
  attack alike), so the governor bound reflects the true achievable ceiling
  at that point in the stream, not just the benign subset.
- The governor is a safety net that applies regardless of `estimator` — keep
  it active even when `estimator="median_std"` is selected for the ablation
  row, so the legacy row still terminates gracefully instead of reproducing
  the exact zero-alert failure (it will instead show "capped at ceiling",
  which is itself useful ablation evidence).
- `sweep_adaptive_alpha()` (already in cell 10, unchanged in signature) needs
  one new pass-through: forward `estimator` / `target_percentile` into the
  `AdaptiveThresholdSimulator(...)` it constructs, so the existing
  `RUN_ALPHA_SWEEP` infrastructure keeps working without a second rewrite.
